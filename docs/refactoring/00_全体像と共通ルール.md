# リファクタリング指示書 00: 全体像と共通ルール

**この文書群は、AIエージェントが1ステップずつ読んで実行するための作業指示書である。**
実行者はまず本書(00)を全部読み、その後 step0 から順に、**1ステップずつ**実行すること。
ステップを飛ばすこと、複数ステップをまとめて実行すること、指示にない「ついでの改善」を行うことをすべて禁止する。

---

## 1. このリファクタリングの目的

1. **共通化と関数の独立性**: 1417行に肥大化した `Secure/Core/Src/telemetry.cpp` を機能単位に分割し、各ファイルを疎結合にする
2. **基板非依存化**: 今後この評価ボード(B-U585I-IOT02A)から自作基板(STM32系・TrustZoneあり)へ移行する。「port層(基板依存ファイル)を差し替えれば動く」構造にする
3. **Secure/NonSecure原則の形式化**: ファーム更新・ファーム判定/実行・UART処理・状態監視 = Secure(更新しない基礎領域)。センサー等 = NonSecure(OTAで更新)。TrustZone無し基板への移植も容易な境界構造にする

## 2. 目標アーキテクチャ

### レイヤ構造（ディレクトリではなくファイル名で表現する）

**重要な制約**: 新規ファイルは必ず `Core/Src` / `Core/Inc` 直下に置くこと。
理由: このプロジェクトのEclipse `.project` は特殊なlinkedResources構造を持ち、`Core/Src` 以外に置いたファイルはビルド対象にならない（登録手順が複雑でエラーを誘発する）。レイヤはファイル名プレフィックスで表現する。

```
【契約層】(ヘッダのみ。自作基板でも一切変更しない)
  NonSecure/Core/Inc/comm_api.h      ... NS→Secure通信API(step2で新規)
  NonSecure/Core/Inc/board_io.h      ... LED/ボタン契約(step1で新規)
  NonSecure/Core/Inc/sensors.h       ... センサー契約(既存)
  NonSecure/Core/Inc/ns_audio.h      ... 音声契約(既存)
  Secure/Core/Inc/comm_backend.h     ... 通信サービス移植境界(step7で新規)
  Secure_nsclib/comm_dto.h           ... FullStatus_t 165バイト(既存・凍結)

【コア層】(基板非依存。自作基板へそのままコピーする)
  NonSecure/Core/Src/app_loop.c      ... ACTIVE/IDLEステートマシン(step2で新規)
  NonSecure/Core/Src/ns_audio.c      ... 音声RMS/波形計算(既存)
  Secure/Core/Src/comm_service.cpp   ... Service本体(step6でtelemetry.cppをリネーム)
  Secure/Core/Src/ota.cpp            ... OTA機構(既存)
  Secure/Core/Src/boot_guard.cpp     ... 起動監視(既存)
  Secure/Core/Src/frame_codec.c      ... フレームプロトコル(既存)

【port層】(基板依存。自作基板ではこれらだけ再実装する)
  NonSecure/Core/Src/board_io.c      ... LED PH6/PH7, ボタンPC13(step1で新規)
  NonSecure/Core/Src/sensors.c       ... BSPセンサー実装(既存)
  Secure/Core/Src/comm_wifi.cpp      ... EMW3080 Wi-Fi/TCP(step3で新規)
  Secure/Core/Src/comm_ble.cpp       ... WB5MMG BLE(step4で新規)
  Secure/Core/Src/comm_uart.cpp      ... VCP非同期TX(step5で新規)
  Secure/Core/Src/audio_capture.cpp  ... MDF1音声キャプチャ(step5で新規)

  Secure/Core/Src/console.cpp        ... UART RX DMA(既存)

【アダプタ層】(TrustZone形態依存)
  Secure/Core/Src/secure_nsc.c       ... CMSEゲートウェイ(既存。TZ基板用)

```

### 設計方式: リンク時差し替え

関数ポインタの構造体(ops table)は使わない。**契約 = ヘッダの関数宣言、実装 = portファイル**。
自作基板への移行時は、port層ファイルを新基板用に同名関数で再実装するだけ。実装漏れはリンクエラーで検出される。

## 3. 絶対に守るルール（ガードレール）

以下に違反する変更は、たとえコードが「改善」されるように見えても**禁止**。

1. **FullStatus_t は165バイト不変**。`Secure_nsclib/comm_dto.h` L62・`Secure/Core/Inc/telemetry.hpp` L57 の static_assert を削除・変更しない。構造体メンバの追加・削除・並び替え禁止(PCパーサと3点一致が必須)
2. **OTA信頼ルートを壊さない**: `handleFrame` / `ota::Manager` / `frame_codec` / `Frame_Decoder` をNonSecureへ移動しない。`secure_nsc.c` の `cmse_check_address_range` 検証を弱めない
3. **機械的移動のみ**: 関数を移動するとき、本体は**コメントも含めて1文字も変えない**。タイムアウト値・リトライ回数・NVIC優先度(12/13/14)・ボーレート・DMA属性フラグ・比較演算子・printf文字列の変更禁止。特に過去のバグ修正を説明する長いコメントブロック(pollTcpのIDLEスキップ理由、processRxByteの'a'/'s'処理理由、NVIC_SystemReset採用理由など)は**本体ごと移動して保持**する
4. **境界API凍結**: `Comm_*` 7関数と `CommBridge_*` のシグネチャ・戻り値の意味(COMM_POLL_NONE/ACTIVITY/BYTE)を変更しない。NonSecureからSecureへ関数ポインタを渡すコードを書かない
5. **インフラ凍結**: `.ioc` ファイルの再生成禁止。`Secure/Core/Src/main.c` の `MX_GTZC_S_Init` / GPIO NSEC設定 / Stage-0ジャンプフロー、リンカスクリプト(*.ld)、`partition_stm32u585xx.h`、startupファイル、`ota.cpp` のアドレス定数(`kNsFlashBase`/`kNsFlashSize`等)に触れない
6. **初期化順序維持**: `CommInit()` 内の「ボーレート設定→`init()`→`setNsDriven(true)`」の順、`Service::init()` 内の「initSensors→initAudio→initMcuInfo→initRadio」の順を変えない。`App_Main()`(Secureローダー常駐パス)が `CommInit()` を再利用し `setNsDriven(false)` する構造を壊さない
7. **1ステップ = 1コミット**。実機検証がPASSするまで次のステップに進まない。NonSecureを変更するステップでは `NS_APP_VERSION`(NonSecure/Core/Src/main.c L42)を+1する
8. **HALコールバックは1ファイルに1定義**: `HAL_UART_TxCpltCallback` / `HAL_UART_RxCpltCallback` / `HAL_GPIO_EXTI_Rising_Callback` / `BSP_AUDIO_IN_*_CallBack` は、移動後にプロジェクト内で定義が1箇所だけであることを確認する。二重定義はリンクエラーになるが、**定義漏れはHALのweakデフォルトに落ちてエラーなしで機能が死ぬ(サイレント故障)**。だから各ステップの実機検証を省略してはならない
9. **volatile修飾を落とさない**: `uartTxBusy` / `bleLinkOk` / `bleConnected` / `nsActivity` / `g_AudioEvents` / `g_AudioErrors` / `wifiLastEvent` は割り込みと共有される。移動時にvolatileを維持する
10. **ビルド・検証は常にDebug構成**。NonSecureのRelease構成にはBSPインクルードパスが無い既存の不整合があるため使わない

### ビルド（Git Bash構文）

```bash

"<CUBEIDEC>" --launcher.suppressErrors -nosplash \
  -application org.eclipse.cdt.managedbuilder.core.headlessbuild \
  -data "<HWS>" -importAll "<REPO>" \
  -build "B-U585I-IOT02A_Secure/Debug" -build "B-U585I-IOT02A_NonSecure/Debug"

  -application org.eclipse.cdt.managedbuilder.core.headlessbuild \
  -data "<HWS>" \
  -build "B-U585I-IOT02A_Secure/Debug" -build "B-U585I-IOT02A_NonSecure/Debug"
```

**期待結果**: 各ビルドの末尾に `Build Finished. 0 errors`。warningはSecureの既存2件(`g_AudioEvents`/`g_AudioErrors` の extern初期化警告)のみ許容。それ以外のwarningが増えたら原因を調査すること。

**トラブル対処**:
- `Workspace already in use!` → `<HWS>/.metadata/.lock` を削除して再実行
- `-importAll` で `No file system is defined for scheme` → パスをWindows形式(`d:\...` または `d:/...`)で渡しているか確認
- 新規 `.cpp`/`.c` が `undefined reference` になる → Core/Src直下に置いたか確認。置いてあれば `-importAll` 付きで再ビルド

### 書き込みとリセット

```bash
# 書き込み(Secure→NonSecureの順。変更した側だけでよい)
"<CLI>" -c port=SWD mode=UR -d "<REPO>/Secure/Debug/B-U585I-IOT02A_Secure.elf" -v
"<CLI>" -c port=SWD mode=UR -d "<REPO>/NonSecure/Debug/B-U585I-IOT02A_NonSecure.elf" -v
# リセット(起動)
"<CLI>" -c port=SWD mode=UR -rst
```

**注意**: リセット後、Wi-Fi/BLE初期化に**約10〜15秒**かかる。この間UARTは起動ログのみでテレメトリは流れない。検証スクリプトの実行はリセットの12秒後以降にすること。

### 実機検証スクリプト（共通、これをそのまま使う）

検証はST-LINK VCP (COM9, 921600baud) 経由。以下のスクリプトを `<REPO>/docs/refactoring/verify_regression.py` として使う(step0で作成する)。

```bash
cd "<REPO>" && python docs/refactoring/verify_regression.py
```

**PASS判定基準**(スクリプトが自動判定して最後に PASS/FAIL を印字する):
1. ACTIVE維持: keep-alive(1秒毎に`\x00`)送信中、5秒間で **150フレーム以上** 受信
2. センサー生存: `tof_mm` の値が期間中に **2種類以上** 変動(固定値=センサー死亡)、`temp_c` が10〜60の範囲
3. IDLE遷移: keep-alive停止5秒後、フレーム受信が**停止**する
4. IDLE復帰: keep-alive再開後8秒間で **100フレーム以上** 受信
5. 音声: `'a'`送信後3秒でCMD_AUDIO(0x03)フレームを **50個以上** 受信、`'s'`で停止
6. OTA照会: CMD_STATUS_REQ(0x06)へCMD_STATUS_RESP(0x07)応答が返る

## 6. 行番号についての注意

各ステップの「移動する関数」表の行番号は、**step0時点(コミット `3c676b5` 以降のmaster)の実測値**である。
先行ステップの実行によって行番号は数行ずれることがある。**行番号は目安とし、関数名で検索して特定する**こと。関数名・シグネチャ・本体先頭のコメントが表と一致することを確認してから移動する。
